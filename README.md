## О проекте

Боты – канал взаимодействия клиентов и сотрудников транспортно-логистической компании
**«ЛогиХаб»** (вариант 15 «Процесс управления логистикой»). Каждый этап BPMN-модели процесса
выполняется в одном из двух ботов, документы процесса формируются в PDF.

| Этапы BPMN | Что происходит в боте | Кто |
|---|---|---|
| 1–2, 6 | Заявка за 9 шагов: город, груз, вес, места, адрес, получатель, дата отгрузки, страховка, комментарий; расчёт стоимости с разбивкой и срока | Клиент |
| 3–5 | Проверка заявки: подтвердить, вернуть на уточнение с комментарием (клиент правит адрес, получателя, места и отправляет повторно) или отклонить | Менеджер ↔ клиент |
| 7 | 📄 **Договор-счёт** в PDF приходит клиенту | Менеджер → клиент |
| 8–9 | «Я оплатил», подтверждение поступления; напоминание за сутки и **автоотмена через 3 дня** без оплаты | Клиент, менеджер, система |
| 10–13 | Комплектация, контроль In Full с циклом «докомплектовать», 📄 **ТТН** в PDF | Склад |
| 14–16 | Назначение водителя под тип транспорта, начало рейса: клиент получает водителя, машину, госномер и ТТН | Диспетчер → клиент |
| 17–18 | Отклонение от графика: причина (трасса, погода, паром Ванино – Холмск…), новый срок, уведомление клиента | Диспетчер → клиент |
| 19–22 | Доставка и приёмка: 📄 **акт приёмки** в PDF | Клиент |
| 20–23 | Претензия: вид замечания, описание, до 5 фото; решение – компенсация, довоз или отказ | Клиент ↔ менеджер |
| 24–26 | Автоматическое закрытие заказа с расчётом On Time / In Full, оценка клиента 1–5 | Система, клиент |
| KPI | Сводка по заказам ботов (OTIF, оценки, оплаты, выгрузка CSV) и KPI дашборда с графиком | Менеджер |

## Возможности

- **Два бота**: клиентский [@logihub_logistics_bot](https://t.me/logihub_logistics_bot) и рабочее место сотрудников [@logihub_manager_bot](https://t.me/logihub_manager_bot) (вход по коду доступа). Уведомления каждой роли приходят в её бот.
- **Клиент**: знакомство (организация, телефон кнопкой «Отправить мой номер»), заявка с расчётом, «🗂 Мои заказы» с действиями по статусу, документы (счёт, ТТН, акт), отслеживание по номеру, тарифы и сроки, «💬 Написать менеджеру».
- **Сотрудник**: разделы по этапам процесса – новые заявки, оплаты, склад, рейсы, претензии; поиск заказа с историей; ответы клиентам; сводка с OTIF и выгрузкой CSV для Excel; KPI дашборда.
- **Статусы** повторяют потоки BPMN; недопустимые переходы блокируются (`TransitionError`), например рейс нельзя начать без водителя.
- **Документы в PDF** (reportlab): договор-счёт, ТТН, акт приёмки; дата документа – момент соответствующего этапа.
- **KPI из дашборда**: пакет [`logihub-dashboard`](https://github.com/starpxand/logihub-dashboard), поэтому показатели в чате и в дашборде совпадают.

> Реквизиты компании в документах условные – учебный проект КнАГУ.

## Установка и запуск

1. Создайте у [@BotFather](https://t.me/BotFather) два бота – клиентский и для сотрудников – и получите токены.
2. Установите зависимости и настройте окружение:

```bash
git clone https://github.com/starpxand/logihub-telegram-bot.git
cd logihub-telegram-bot
python -m venv .venv
# Windows: .venv\Scripts\activate    Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # укажите BOT_TOKEN и MANAGER_BOT_TOKEN
python -m logihub_bot
```

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | токен клиентского бота от @BotFather | – (обязательно) |
| `MANAGER_BOT_TOKEN` | токен бота сотрудников от @BotFather | – (обязательно) |
| `MANAGER_CODE` | код доступа к рабочему месту сотрудника | `logihub-manager` |
| `DB_PATH` | файл базы SQLite | `logihub_bot.sqlite3` |
| `ORDERS_CSV` | выгрузка заказов для KPI | `data/logistics_orders.csv` |
| `DASHBOARD_URL` | адрес веб-дашборда | `http://127.0.0.1:8050` |

## Как пользоваться

**Клиент:** `/start` → «📦 Новая заявка» → данные груза → «✅ Отправить заявку». Договор-счёт придёт в чат –
после оплаты нажмите «💳 Я оплатил». Бот сообщит о складе, выезде (водитель, машина, ТТН), задержках и доставке;
после доставки – «✅ Принять без замечаний» (акт) или «⚠️ Есть замечания» (претензия с фото).

**Сотрудник:** `/start` → код доступа → разделы «📋 Новые заявки», «💳 Оплаты», «🏭 Склад», «🚚 Рейсы»,
«⚠️ Претензии», «🔎 Найти заказ», «📈 Сводка», «📊 KPI дашборда».

| Команда | Действие |
|---|---|
| `/start` | главное меню (в боте сотрудников – вход) |
| `/new` | новая заявка |
| `/orders` | мои заказы |
| `/status LH-20001` | статус и история заказа |
| `/tariffs` | тарифы и сроки |
| `/support` | написать менеджеру |
| `/kpi` | KPI доставки с графиком (бот сотрудников) |
| `/logout` | выход из рабочего места (бот сотрудников) |
| `/cancel` | прервать ввод |

## Тестирование

```bash
pip install pytest
pytest -v
```

44 автотеста: тарифная модель и страховка, все переходы BPMN (циклы уточнения и докомплектации,
ветка претензии, отмена до оплаты, водитель под тип транспорта), On Time / In Full и OTIF, сроки оплаты,
PDF-документы, миграция старой базы и **сквозные сценарии обоих ботов** – обновления Telegram проходят через
диспетчеры aiogram, Bot API заменён фейковой сессией, которая проверяет HTML-разметку, лимиты длины
и размер callback-данных. Протокол – [`docs/TESTING.md`](docs/TESTING.md).

## Структура

```text
logihub-telegram-bot/
├── logihub_bot/
│   ├── __main__.py     # запуск двух ботов и контроля оплаты
│   ├── config.py       # настройки из .env, сведения о компании, хабаровское время
│   ├── pricing.py      # расчёт стоимости, страховки и срока (этап BPMN 6)
│   ├── storage.py      # SQLite: клиенты, заказы, история, водители, претензии, OTIF
│   ├── client.py       # клиентский бот
│   ├── manager.py      # бот сотрудников: менеджер, склад, диспетчер
│   ├── documents.py    # PDF: договор-счёт, ТТН, акт приёмки
│   ├── jobs.py         # напоминание и автоотмена неоплаченных заказов
│   ├── notify.py       # уведомления между ботами
│   ├── analytics.py    # KPI и графики через logihub-dashboard
│   ├── keyboards.py    # клавиатуры
│   └── texts.py        # тексты сообщений
├── data/               # выгрузка заказов для KPI
├── tests/              # pytest
└── docs/               # аватарки, протокол тестирования
```
